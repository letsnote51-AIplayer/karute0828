# ネイルサロン顧客理解カルテ UIモック仕様書

- 文書種別: SNS投稿撮影用UIモック仕様
- 作成日: 2026-08-28
- ステータス: 承認済み
- 対象: スマートフォン専用Web画面

## 1. 目的

ネイルサロン向け顧客カルテの利用イメージが10〜15秒で伝わる、投稿撮影用のUIモックを作る。価値の中心は「お客様の好み、爪の状態、アレルギー、注意事項、前回の会話を忘れず、自然に接客できること」とする。実際の業務利用やデータ管理は目的に含めない。

## 2. 成果物

- Reactで表示する4つの静的画面
- スマートフォンで片手操作しやすい縦型画面
- 固定された架空顧客データ
- 投稿動画用の画面遷移
- 編集・保存しているように見える演出

## 3. 画面

### 3.1 ダッシュボード

- アプリ名 `Atelier Note`
- 登録顧客数、今月の来店数、注意事項がある顧客数
- 最近更新した顧客、最近の施術写真
- 顧客検索欄

投稿では検索欄に「佐藤」と入力済み、または入力演出ができる状態にする。

### 3.2 顧客一覧・検索結果

- 顧客写真またはイニシャル
- 顧客名、フリガナ
- 最終来店日、来店回数
- 好みのタグ
- アレルギー・注意事項の有無
- 担当者

「佐藤 美咲」を先頭に表示し、クリックすると顧客カルテへ遷移する。

### 3.3 顧客カルテ詳細

最重要画面。顧客概要、重要警告、好み、爪の状態、前回の会話、接客時の注意、過去の施術写真、接客タイムラインの順で表示する。

中心顧客の固定データ:

- 氏名: 佐藤 美咲
- 来店回数: 12回
- 好きな色: ベージュ、ボルドー、くすみピンク
- 好きな系統: シンプル、上品、オフィス
- 爪の形: オーバル
- アレルギー: アクリル系商材に注意
- 爪の状態: 右手人差し指が薄くなりやすい
- 接客時の注意: 強いプッシャー圧を避ける
- 前回の会話: 9月に京都旅行を予定。秋色ネイルを検討中
- 次回聞きたいこと: 京都旅行の予定

### 3.4 会話メモ編集

- 前回の会話要約
- 次回聞きたいこと
- 接客時の注意
- キャンセル、保存ボタン

保存時に「カルテを保存しました」というトーストを表示してカルテへ戻る。内容は永続化しない。

## 4. 投稿用デモ導線

1. ダッシュボードで「佐藤」を検索している状態を見せる。
2. 「佐藤 美咲」をクリックする。
3. アレルギー警告を見せる。
4. 好み、爪の状態、前回会話を見せる。
5. 会話メモ編集を開く。
6. 保存をクリックする。
7. 保存トーストを表示する。

撮影尺は10〜15秒を基準とする。

## 5. デザイン

コンセプトは「高単価ネイルサロンの、上品で信頼できる顧客カルテ」とする。

- 背景: アイボリー〜淡いグレージュ
- メイン: チャコール
- アクセント: 落ち着いたゴールドまたはトープ
- 警告: 彩度を抑えたボルドー
- 成功: 深いグリーン
- 角丸と影: 控えめ
- 写真: ネイル写真が自然に目立つサイズ
- 書体: 日本語の可読性を優先したゴシック体
- アニメーション: 150〜250ms

## 6. スマートフォンUI

- 基準画面は390×844pxとする。
- 保証対象は横幅375〜430pxとする。
- 画面全体を1カラムの縦スクロールにする。
- 主要ナビゲーションは画面下部に固定する。
- ページタイトルと戻る操作は上部ヘッダーに配置する。
- 顧客一覧は縦型カードにする。
- 施術写真は横スワイプできるカード列にする。
- メモ編集はモーダルではなく全画面表示にする。
- 保存などの主要ボタンは親指が届きやすい画面下部へ配置する。
- タップ領域は44px以上、主要ボタンは48px以上にする。
- アレルギー警告はカルテを開いた直後に見える位置へ置く。
- 横幅430pxを超える画面では最大幅480pxで中央表示し、PC専用レイアウトは作らない。

## 7. 技術構成

- React、TypeScript、Vite
- React Router、Tailwind CSS、Lucide React
- TypeScriptファイル内の固定データ
- バックエンド、localStorage、外部APIなし

## 8. 必要な操作

- ダッシュボードから固定の検索結果へ遷移
- 顧客カードからカルテへ遷移
- カルテからメモ編集を開く
- 保存ボタンで成功トーストを表示
- 下部固定ナビゲーションと上部の戻る操作

本物の検索ロジック、データ更新、永続化は作らない。

## 9. 作成しないもの

- localStorage、データベース、クラウド同期
- ログイン、アカウント、権限
- 本物の検索、絞り込み、並び替え
- CRUD処理、画像アップロード、入力チェック
- 複雑な状態管理、本番エラー処理、自動テスト一式
- 予約、決済、会計、メッセージ、AI、外部連携
- 本番公開

## 10. 素材と安全性

- 氏名、電話番号、会話、健康・アレルギー情報はすべて架空とする。
- 実在する顧客情報を使用しない。
- 写真は生成素材、利用許諾済み素材、または権利上問題のない素材だけを使う。
- 実際に導入済み・販売中と誤認させる表現を使わない。

## 11. 完成条件

1. 4画面が存在する。
2. 横幅375〜430pxで表示が崩れず、横スクロールが発生しない。
3. ダッシュボードからカルテ、メモ編集、保存演出まで遷移できる。
4. アレルギー、好み、爪の状態、前回会話が一目で分かる。
5. 警告がアイコンと文章でも伝わる。
6. 10〜15秒の投稿動画を撮影できる。
7. 実在する顧客情報や無許諾素材を含まない。
8. 未実装機能を利用可能に見せない。

## 12. 制約

- 投稿検証用UIモックであり、本番運用しない。
- PC・タブレット専用レイアウトは作らない。
- 入力保持、正確な集計、データ整合性を保証しない。
- 投稿の反応が良かった場合に限り、別仕様としてMVP化を検討する。
